# V0.3 引导情境自查

日期：2026-11-10。方式：同一 AI 重新读取 guide、review、improve 及操作协议后进行情境推演，并与隔离协议测试对照。不是独立代理、新上下文或真实客户体验验证。模拟输入未进入客户记录。

| 输入或情境 | 实际自查判断与下一步 | 相邻行为核对 |
|---|---|---|
| “这个世界观我已经给过你了，怎么又问？” | 先定位原件与理解记录，补读后只问缺口；记录当前纠正来源，查明是漏读还是版本冲突，再决定改触发还是规则。 | 没有资料时允许自然语言起步，不要求客户补齐专业文档。 |
| “我不喜欢这次的红色，换成灰色。” | 归为本项目画面需求，进入美术/设计决策；不能归纳为永久禁止红色。 | 客户明确说“以后讲解别用术语”则是协作偏好，可小范围修改引导。 |
| “步骤看不懂，你自己处理。” | 先承担已有能力和授权内的操作，改为具体可见结果与必要客户动作；不能把这句话当作付费、发布或扩大权限。 | Unity 无法运行时给准确操作与观察点，保留待验证。 |
| 任务完成、阶段验收、第五项完成或第七天有新资料 | 根据完成事件/来源游标决定任务收尾或集中复盘，实际看过材料才登记。任务收尾不能清掉集中复盘计数。 | 没有新增资料时不为了日期制造规则或空报告。 |
| 只能读到当前聊天，历史记录不可用 | 标明 unavailable/partial；增量记录实际读到的位置，不把摘要伪装成原话，不扫描其他项目。 | 能读取本项目历史时按稳定来源 ID 去重，冲突拒绝覆盖。 |
| 改完以后客户没有再说话 | 保留“试用中”，不能写有效；下一次同类使用或明确反馈才登记观察。 | 新问题复发时建立关联候选，保留旧结果；新增证据回到待核实。 |
| 改规则后更难用，客户又自己修改了文件 | 先判断反效果，回退核对全部文件，发现后改内容即停止覆盖并按差异合并。 | 中断恢复可从 reverting 继续；prepare 后完全没改可 cancel，不会永久卡在修改中。 |
| 网页把协作抱怨关联到了已验收任务 | AI 核实原话后 route_feedback，保留来源和分类理由；回答后 resolve，改进试用继续跟踪。 | 真正的游戏缺陷仍进入原有需求/重开/回归流程，不能靠分类绕过验收。 |

## 两轮自审结论

正确性检查：主引导存在触发入口；新技能的读写、来源游标、四类验证、效果观察与回退命令都能对应实际代码。自查修复了“只同步索引即视为核实”“新证据未重新归因”“prepare 后未改无法取消”的状态漏洞。原始材料不是新增授权，客户创作变化不固化为永久规则。

必要性检查：沿用现有本地服务、JSON 与写锁，只增加一份独立账本和一个 skill；不新增数据库、模型 API、聊天数据库扫描或后台驻留服务。客户只需自然表达，内部记录由 AI 填。恢复必须比较本次前后内容，是为防止覆盖后改文件所需的完整性检查，不做无关哈希比对。

尚待验证：真实新手跨多个任务使用后是否减少重复解释、返工和困惑；真实客户电脑上的可选定时配置。当前不能声称自我迭代已经改善了客户体验。
