# V0.3 持续改进机制验收

日期：2026-11-10。范围：工作流工具、skills、客户材料和本地网页；不是 Unity 游戏验收。

## 交付机制

- 七个 skills：总引导默认检查纠正、每步收尾、阶段/5 项任务/7 天有新材料的复盘触发。
- 独立工作流改进记录，保留来源、覆盖缺口、核实、修改、验证、试用、效果与恢复历史；游戏进度仍用 state.json。
- improvement.py 提供来源去重、版本冲突检查、修改前后备份、四项验证门槛、后续效果证据、撤回及中断恢复；没有 Git 也可使用。
- 网页新增改进页与协作反馈分类，原游戏验收和反馈原文保持各自语义；22 条推进提示词。
- 客户指南、操作协议、案例模板、发送说明和旧包升级说明同步更新。

## 验证证据

最终 63 项自动测试通过、7 个 skills 官方校验通过、82 篇 Markdown 无失效链接，JavaScript 语法与差异检查通过。详细结果见同目录 `V0.3自动测试.txt`、`V0.3静态检查.txt`。用隔离目录验证完整游戏状态生命周期及改进状态机，未向客户初始记录写入模拟反馈。游戏 state revision 1、20 项 pending、0 条反馈；改进 revision 0、0 信号、0 项改进。

浏览器实测使用 CUA 和端口 8768 的隔离副本：

1. 改进页空状态、按钮和状态文案正常；本次实际展示空状态、试用中、已撤回，其余状态转移由协议测试覆盖。
2. 协作反馈分类、文字草稿跨页面和刷新保留；保存后分类正确、草稿清空、记录进入隔离 state。
3. CLI 写入试用/撤回后网页自动同步，来源读取缺口可见，案例可打开。
4. 损坏改进 JSON 后改进页提示错误，首页仍可读；恢复文件后页面恢复。
5. 新复盘按钮点击出现复制成功提示；浏览器工具读取剪贴板为空，未证明跨应用粘贴。提示词原文可在提示词库读取，普通浏览器的实际粘贴仍须客户环境确认。

## 边界

默认在客户打开项目与 Codex 协作时执行，不伪装成后台常驻智能体。没有创建开发者机器定时任务；客户需要时再按其实际宿主配置。未读取客户历史聊天、未改变全局记忆、未修改真实客户游戏状态。真实客户使用改善、干净机器部署、Unity 运行/构建、目标设备和正式发布尚未验证。
