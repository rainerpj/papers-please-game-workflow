- 状态工具：验证门槛、版本冲突保护、原子保存、备份、任务扩展、重开与下游证据归档。

## 审阅发现与修正

- 初始化配置解析失败：修正配置字段，并把配置读取移到复制前，避免未来失败时先复制部分记录。本次已复制文件保留，完成种子初始化。
- 已验收任务收到问题反馈：改为保留历史并重开关联任务与下游阶段，不要求客户先懂重开操作。
- HTTP 测试路径默认参数捕获：改为显式传入状态路径与根目录。首轮产生的一条隔离测试文本误入空白项目，已恢复初始化副本；后续断言验证写入测试目录，真实项目没有模拟反馈或完成状态。
- 旧证据随任务目标变化继续生效：增加必须先重开的约束。
- 新文档目录不能在已打开网页出现：加入目录轮询更新；未提交反馈保持原文。
- 待客户回答的问题：增加 question 字段、首页展示与完成门槛；保存回答不自动当作决定已处理。
- 证据可能是日志或截图：增加受登记路径限制的证据查看，支持文本、JSON 与常见截图格式。

必要性审查保留 Python 标准库服务和原生网页，不增加数据库、账户体系、云服务或模型 API。需求、状态、提示词、阶段门槛各有单一维护位置。完整游戏内容量和发行渠道未由 AI 预设。

## 未验证与限制

- 没有运行客户 Unity 工程、编译 C#、制作客户正式资产或发布游戏。
- 没有由真实零经验客户从概念走到发行；skills 为格式校验和静态情境走查，未执行独立代理的行为评测。
- 记录校验只能检查结构、引用文件和前置条件，不能代替人工核对证据真实性及体验质量。
- 本地网页不会自动执行 AI；客户需把提示词粘贴到项目对话，反馈需 AI 读取处理。
- Python 和 Unity 需要在客户机器准备，未验证一台全新客户电脑的安装全过程。
- 暂无正式竞品细节研究结果；按客户要求，研究能力随实际疑点主动触发，而不是虚构一份先验结论。
- 未进行 Git 提交、推送或对外发布。
