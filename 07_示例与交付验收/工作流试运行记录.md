# 工作流试运行记录

日期：2026-11-10。对象：工作流包 V0.1，不是客户游戏。状态工具和网页在隔离测试数据上执行；真实项目保持未开始。

## 已执行的工具链试运行

- 使用空白种子初始化 20 个基线任务；按 10 个阶段依次写入测试夹具证据并验收，到维护交接全部可达。此处的证据是测试夹具，不是游戏运行证据。
- 尝试缺少证据、缺少两轮审查、前置阶段未完成、客户验证未记录时直接完成：更新被拒绝。
- 新增范围、重开任务、同阶段依赖、后续阶段回退、旧证据归档、开放问题阻塞、解决反馈再验收：执行结果符合协议。
- 同一类别先通过后失败，验收被阻止；有证据的任务改目标需要先重开。
- 两个版本并发保存，旧 revision 被拒绝；锁冲突、损坏 JSON 不会自动清空记录。
- 浏览器端记录反馈、查看文档、复制提示词、外部文件更新同步、保留未提交草稿、损坏数据提示与恢复：已执行。

## Skills 的静态情境走查

本节是同一 AI 对技能规则的分轮审阅，不是独立代理的行为测试，也不是实际零经验客户试用。

| 输入情境 | 规则应导向的行为 | 本次检查结论 |
|---|---|---|
| “就做 Papers, Please 那种” | 保留已知类型，从具体审核情境补齐需求 | 总规则、引导和设计入口一致 |
| “剧情不知道怎么塞进去” | 主动研究相关作品的实际呈现，解释适用条件，做事件原型 | 设计、参考和提示词都包含入口 |
| “画面乱，但说不出原因” | 从信息层级和用途分析，按需找参考，先试样本 | 美术提示词与游戏内验收分开 |
| “代码写完就算好了吧” | 区分静态、Unity 运行、构建和独立运行证据 | Review 规则和状态门槛一致 |
| “先做个能玩的就结束” | 识别是否客户明确变更目标；现有完整交付不能被默认缩成原型 | 完整范围与中间里程碑明确分离 |
| “我想改之前的规则” | 解释影响、按授权决定、重开受影响任务并保留历史 | 文档与程序支持同一路径 |
| “发布后玩家说存档坏了” | 定位版本、保留备份、修复回归、核对发布授权 | 维护阶段与提示词覆盖 |
