# 从这里开始

你已经决定做 Papers, Please 这种审核判断游戏。接下来不用重新选类型，也不用先学会写程序。你负责说明想要的体验、做关键选择、实际玩一玩；AI 负责把想法拆成步骤并执行检查。

## 第一次准备

1. 把整个交付文件夹放在固定位置，保留所有子目录和隐藏的 `.agents` 文件夹。
2. **开始前，把你已经有的世界观、故事、角色设定、玩法笔记、参考图等发给 Codex，或放到文件夹里的 `00_客户资料`。** Word、PDF、文本、图片都可以先提供，不需要重写；哪个版本最新、哪些已决定或只是随手想法，知道的话顺便说一句。
3. 在你使用的 Codex 中打开这个文件夹作为项目。让 AI 确认能读取 `AGENTS.md`、`项目记录/state.json` 和你提供的资料。AI 应先用简单的话总结已有内容，只问矛盾、遗漏和本步必须决定的事情。
4. 双击 `启动进度网页.cmd`。出现本地地址后，浏览器会打开进度页。这个窗口保留运行，关掉它会停止网页。
5. 如果提示需要 Python，把提示原文告诉 AI：“请帮我检查这个工作流需要的 Python 环境，并启动网页。”本包需要 Python 3.10 或更高，不需要额外 Python 包。
6. 在网页点击“继续这一步”，粘贴到 AI 对话；或直接使用下方开场白。

> 请先阅读我提供的附件和 `00_客户资料`。我已经有一些设定，不要让我从零讲一遍。先告诉我你理解了什么，哪些文件没读到、哪些说法有冲突，再按 Papers, Please 式游戏的工作流继续。每次只问现有资料不能回答且现在必须决定的问题。

如果附件打不开，AI 应明确指出是哪份文件、缺哪部分，并给你最简单的补充方式。不要因为一份资料读取失败而重新写全部设定。`00_客户资料` 里的原件会保留，AI 的整理写入 `项目记录`；网页不负责上传或解析附件。

## 怎样知道准备好了

你能看到网页的“今天做什么”，AI 能读到真实项目记录，并能解释下一步。请告诉 AI 你实际完成了哪些操作，由 AI 登记结果；任务不会因为页面打开就自动全变绿色。

Unity 在制作玩法原型前准备。AI 应先检查你的电脑和已有工程，再帮助选择合适版本，记录固定版本和安装模块。没有工程时通过 Unity Hub 建立 2D 工程；菜单与模板按你实际安装版本核对，不要求你猜选项。参见 [Unity Hub 官方说明](https://docs.unity.com/en-us/hub)。

网页离线可用；AI 对话、联网参考、图片生成与软件安装各自需要相应服务和连接。此包不包含这些服务账户。

## 第一次同步也要试一下

让 AI 按 [首次准备规范](../02_工作流规范/首次准备与能力预检.md) 检查当前电脑并写入本步操作卡。你应能在首页打开说明、看到记录版本改变、保存一条自己的反馈并得到 AI 答复。打不开时读 [第一次打不开怎么办](07_第一次打不开怎么办.md)。之后看 [从样例做到完整游戏](08_从样例做到完整游戏.md)，不需要一次读完所有技术文件。
