# 游戏设计

当前只有类型方向已确定。本文件中的规则须逐条由讨论或验证产生，不能将参考作品机制直接当成项目需求。

## 玩家的一次工作

填写：接到谁/什么材料 → 获取信息 → 对照规则 → 作出决定 → 得到反馈 → 影响后续。先用一例正常情境、一例矛盾情境描述。

## 规则与信息

填写：审核字段、合法性判断、优先级、规则更新时机、可查工具、允许的操作、误判后果、重复操作、超时/暂停、重试与恢复。未采用的机制写清不在范围。

## 故事与内容发展

填写：人物动机、事件进入方式、选择条件与记忆、后果兑现、章节/工作日推进、结局及分支收束。数量引用完整版本范围。

## 产品体验

填写：开始/继续游戏、教学、存档恢复、设置、退出、字体与可读性、输入和声音反馈。具体数值归配置或内容矩阵，避免多处修改。
