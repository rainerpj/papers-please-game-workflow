# 本地进度网页

双击根目录的 `启动进度网页.cmd`。默认地址为 `http://127.0.0.1:8765`，只监听本机。网页不调用模型、不联网同步、不自动开发游戏，也不上传文件。

需要 Python 3.10+，仅用标准库，无安装依赖步骤。其他系统可在根目录运行 `python 04_本地进度网页/server.py --open`。端口已用时指定 `--port 8766`；不要关闭不认识的进程。

## 能做什么

- 今天做什么：按阶段定位最早未验收任务，生成继续提示词。
- 完整开发路线：10 个阶段、基线和新增任务、最低证据、审查结果、未满足条件。
- 指南与项目记录：读取本地 Markdown，显示为易复制的原文，不执行文档中的代码或 HTML。
- 推进提示词：覆盖设计、竞品参考、美术、开发、测试、发行维护等情境。
- 我的反馈：保存想法、问题、实际体验；AI 下次读取后处理。
- 导出进度副本：仅导出 JSON，不包含完整游戏备份。

网页每 3 秒读取状态；AI 通过 workflow.py 更新后可自动显示。正在编辑反馈时不刷新表单以免丢失输入。保存冲突时保留输入，刷新最新状态后再提交。当前网页反馈不是实时 AI 消息，应回到 AI 对话说“读取最新反馈”。

## 面向维护者

服务仅暴露静态网页、允许列表内 Markdown、进度和反馈接口。浏览器不能调用任意命令或直接验收任务。状态协议和 CLI 示例见 [进度数据与同步约定](../02_工作流规范/进度数据与同步约定.md)。

状态写入有 revision、互斥锁、原子替换和历史副本。失败不会静默初始化；错误显示给用户。并发修改要重读合并，不覆盖旧 payload。

验证命令：

```text
python -m unittest discover -s 04_本地进度网页/tests -v
python 04_本地进度网页/workflow.py validate
```

运行环境支持 Playwright 时，可执行 `node 04_本地进度网页/tests/browser.cjs` 对隔离副本做浏览器检查；它会启动自己的服务，不修改真实项目进度。

## V0.2 行为

首页可打开当前操作卡；指南默认显示当前说明和客户指南。反馈草稿按项目保存在当前浏览器，导航/刷新可恢复，保存成功才清理；草稿不是已提交反馈。证据失效显示在对应任务，不阻断全项目读取与反馈。历史验收显示待核实时需 AI 处理。版本快照在首页显示，修改任务不会覆盖历史交付。

AI 可运行 doctor.py 核对当前解释器、读写与状态结构；它不验证 Unity 或客户操作。新增操作与依赖规则以 [进度数据协议](../02_工作流规范/进度数据与同步约定.md) 为准。

## 工作流持续改进（V0.3）

网页“工作流在改进”从独立的 `/api/improvements` 读取记录，显示来源覆盖、待复盘原因、试用效果与缺失证据。记录损坏时本页提示修复，游戏进度仍可读。反馈可选择游戏内容或协作方式；不确定时直接描述，由 AI 分类。协作反馈不阻断游戏验收；反馈原话保留，处理后仍须答复。

AI 用 `python 04_本地进度网页/improvement.py show` 查看，用 `apply --payload 文件.json` 更新；详见 [操作协议](../.agents/skills/beginner-workflow-improve/references/操作协议.md)。网页不直接执行改进，不读取聊天数据库，也不调模型。

“导出记录”只导出游戏 state.json；完整备份请复制整个项目，包括 `项目记录/工作流改进.json` 和 `项目记录/工作流改进证据/变更备份/`。变更备份不通过网页公开，也默认不进 Git；换电脑或恢复必须带上。定时后台执行是客户环境的可选设置，交付包没有预设已运行的定时器。
