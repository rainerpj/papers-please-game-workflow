# 需求与交付目录 V0.1

## 用户确认的目标与修正

1. 客户没有游戏开发经验，需由相对封闭的工作流逐步引导，用自然语言和苏格拉底式提问确定具体需求。
2. 类型已经确定为 Papers, Please 这种；不重开类型选择。具体背景、对象与表现仍按客户描述补齐。
3. 交付包括需求、开发、美术、项目管理 skills，本地可视化进度网页、工作流文档与推进提示词。
4. 每一步自行审核和 Review，解释必须让外行看懂。
5. 竞品参考贯穿早期设计及后续制作；遇到玩法、叙事、美术等不确定，由 skill 主动判断是否查证并告诉客户类似作品如何实践。
6. 目标是完整游戏全生命周期；原型与代表片段为中间阶段，必须覆盖完整内容、产品配套、测试、发行交付与维护。
7. 借鉴已有 TopDown 项目方法：设计与实现分开、正确性与必要性分轮审查、交接可执行、证据分层、复用已有能力、单一状态来源。
8. 客户据述已有世界观等资料。开始前先提醒发到 Codex 或放进 `00_客户资料/`；AI 先清点、实际阅读和提炼，只问冲突与缺口，保留原件与来源。

## 第一版实际目录

```text
README.md / AGENTS.md / 启动进度网页.cmd
.agents/skills/                六个实际可发现的技能
00_客户资料/                    客户已有世界观、剧情、玩法和参考资料入口
01_客户指南/                    六篇面向客户的操作指南
02_工作流规范/                  需求、全流程、沟通、参考、变更、审查、数据协议
03_Skills/                     技能说明和调用入口
04_本地进度网页/                Python 本地服务、状态工具、网页、阶段与提示词数据、测试
05_项目模板/                    概念、设计、完整范围、功能、资产、内容、参考、决定、测试、审查、发行维护、交接
06_推进提示词库/                提示词使用索引；正文由网页同一数据源维护
07_示例与交付验收/              三个教学案例、试运行、检查报告与浏览器截图
项目记录/                       本客户实际记录和 state.json，初始全部未验收
docs/CODEX_HANDOFF.md           当前交接
```

与初稿目录相比，skills 放进宿主支持的 `.agents/skills`，避免手动安装与双份维护；提示词由 JSON 一处维护；新增持续竞品参考、完整内容矩阵和发布维护，替换容易误解为最终目标的“首个可玩版本范围”。
