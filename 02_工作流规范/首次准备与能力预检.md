# 首次准备与能力预检

适用于 T00、换电脑、项目迁移或恢复后。由 AI 执行并把真实结果写进 `项目记录/环境与协作能力.md`，客户不用自诊断环境。先接收已有资料，缺 Unity 不妨碍先理解世界观。

## 第一轮只完成一个小闭环

1. AI 核对当前目录、AGENTS、state 和客户资料能否实际读取；清点 Game 是否真的包含 Assets、Packages、ProjectSettings。没有工程就登记“尚未创建”，不能从文件夹名推断。
2. 在项目根目录运行 `04_本地进度网页/doctor.py`。它只检查本地解释器、临时读写和状态结构；报告输出不代表 Unity、AI 服务或客户操作已验证。由 AI 保存实际输出与时间。
3. AI 填写下表并给出当前可用路线。优先现有环境；软件安装、账号登录由客户完成需要本人操作的部分。涉及费用先说明具体金额与用途，再取得授权。工具名称与菜单按实际版本查证。
4. 为 T00 生成操作卡，使用 workflow.py update 登记 instructions 和 active；网页应出现操作卡入口与新的记录版本。这是第一次写入与同步的真实检查，不能仅打开页面就算通过。
5. 客户打开卡片，告诉 AI 页面显示什么；在网页保存一条实际反馈，如“我能看到操作说明，接下来做什么？”AI 读取反馈并答复、resolve。保留客户原话与实际结果，然后审查 T00。客户没有操作时保持待验证，不生成代答。

| 能力 | 要核实的证据 | 不可用时怎样继续 |
|---|---|---|
| 文件读取与写入 | 读到真实文件；临时文件写入后能读取并清理 | 检查所选项目目录与权限；请客户重新选择项目，不要求重写设定 |
| 本地命令 / Python 3.10+ | 实际命令、版本与退出结果 | 尝试启动器的另一解释器；均不可用时给对应系统的安装步骤；期间先做资料理解 |
| 本地网页 | 首页、版本变化、反馈落盘 | 检查服务窗口与端口；端口占用核实是不是本项目，否则换端口；不可仅反复刷新 |
| AI / 联网参考 | 当前会话实际可用工具及一次针对性读取 | 无联网时用已核验本地参考并标时效；资料不足的事实保持待查 |
| Unity 编辑与运行 | 编辑器路径/版本、工程打开、一次真实运行分别登记 | AI 无编辑器控制时生成准确客户操作卡；编译和运行未回传不能登记通过 |
| 图像 / 音频生产 | 实际可用服务、账户、输出和授权条件 | 采用客户操作、已有合法素材或占位验证路线，按资源生产规范处理 |
| 备份与恢复 | 备份目标、一次隔离副本恢复记录 | 当前先保留本地副本，外部存储/上传需已有授权；不能拿进度导出代替完整工程备份 |

## 卡住的处理

报错原文优先由 AI 读取现有日志；只有拿不到时请客户复制当前看到的句子。先说明“卡在启动网页/打开工程/运行游戏的哪一层”，每次只给一个最小操作。出现两次同类失败且没有新线索时，停止盲目重试，整理已试办法、日志、版本和下一项需要外部提供的条件，转入 [交付维护与求助](交付维护与求助.md)。

客户当前不能使用 AI 时，可先双击网页并查看 [客户故障指引](../01_客户指南/07_第一次打不开怎么办.md)，记录错误后在可用的 Codex 会话继续；网页不会离线替代模型。
