# 提示词结构与资产验收

## 一份提示词包含什么

用途和主体 → 风格基准 ID → 视角与构图 → 配色材质与光向 → 必须保留的空白/轮廓 → 输出比例、尺寸与透明性 → 不要出现的内容。生成工具的参数能力需当次核验；提示词不能保证精确尺寸或透明通道。

可复制结构：

> 制作用于【界面及用途】的【单个资产】。遵循风格基准【编号及具体描述】，采用【视角】，主体位于【位置】，为【动态文字/按钮】保留【区域】。配色【颜色】，光线【方向与明暗】，材质【描述】，轮廓【要求】。输出目标【宽×高/比例】，背景【透明/不透明】。不包含文字、水印、商标、其他资产或展示样机。以游戏内【最终显示尺寸】下可辨认为目标。

例子仅用于说明，不代表已选美术风格：

> 一张横向虚构通行证底板，暖灰纸质、克制的暗绿边框、轻度使用痕迹，正面平视，无透视。左侧留照片框，右侧大面积纯净留白，底部留盖章区；不要写任何姓名、日期、标题或可读文字。单独底板，透明背景，目标比例 3:2。文字和证件内容将在游戏中叠加。

## 同批一致性

固定风格参考图和描述，分资产逐个输出。保存提示词及版本；变化只改需要变化的字段。不要依赖“和上次一样”这种无法交接的描述。拒绝拼图素材、变形的同系列边框、不同光向与多余烘焙文字。

## 接入前与接入后

- 接入前：核对真实像素尺寸、Alpha 通道、边缘白边、裁切、命名和来源。透明棋盘格被画进图中不算透明。
- 接入后：在实际游戏尺寸检查文本对比、按钮可辨性、证件字段排版、遮挡和状态差异。只有完整场景截图或运行观察才能支持“游戏内通过”。
- 记录：提示词完成 → 图片生成 → 导入检查 → 游戏内验证。每一步单独记录，失败资产保留原因但不混入正式清单。
